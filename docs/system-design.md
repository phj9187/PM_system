# PM_system 통합 설계: 확정된 결정

기준일: 2026-11-23. 의사결정, 실행·자원관리, 기록 세 설계 파트를 하나로 묶은 뒤 사용자가 확정한 사항이다. 다른 설계 문서와 다르면 이 문서가 우선한다.

## 확정된 결정

1. **제품 형태**: 대시보드를 하나의 웹사이트로 확장하고, 이후 PC·휴대폰에 설치하는 앱으로 만든다. 앱 틀이 의사결정과 자원관리 전체의 공통 틀이다.
2. **앱 화면**: 대시보드 창과 개인별 임무 창으로 구성한다.
3. **팀 채팅**: 앱 안에 만들지 않고 Discord로 대체하며, 앱 화면과 별도의 묶음으로 둔다. Discord는 앱 화면의 요소들과 상호작용한다.
4. **모듈**: 의사결정 모듈과 실행·자원관리 모듈 두 개다. 별도의 기록 모듈은 없고, 각 모듈이 자기 기록을 직접 담당한다.
5. **기록이 보이는 곳**: 대시보드에서 각 세부 목표·작업을 누르면 뜨는 창에 그 항목의 기록이 쌓인다. 별도의 기록 화면은 만들지 않는다.
6. **원본 기록**: 원본 기록은 앱이 관리한다. 원본 저장소에 들어가는 정보는 Discord에서 왔든 앱에서 왔든 모두 Gemini를 거쳐 정제한다.
7. **Gemini의 역할**: 거의 전 과정에서 정제·중재·통제를 맡는다. 그래서 구조도에 따로 그리지 않는다.
8. **Discord 자동 인식**: 대화를 자동으로 처리해 새 목표와 작업을 인식하고, 앱이 이를 띄워 알린다. 사용자는 최종적으로 추가할지 말지만 정한다.
9. **Notion**: 지금은 쓰지 않는다. 앱 밖 독자가 생기면 붙이는 선택 기능으로 둔다.

공통 원칙: AI의 요약·추천은 제안일 뿐이고, 공식 결정은 사람이 확정한다. API 키·토큰·실제 대화·팀원 개인정보는 공개 저장소, 로그, 백업에 넣지 않는다.

## 구조

```
사람 (팀장·매니저·팀원: 목표 입력, 결정 확정, 작업 수락)
  │
  ▼
앱 틀 (웹사이트 → PC·휴대폰 앱)
  ├─ 앱 화면 ───────────── 상호작용 ───────────── 팀 채팅: Discord
  │   ├─ 대시보드 창 (현황·타임라인·항목 상세)          └─ Discord 채널
  │   └─ 개인별 임무 창 (내 작업과 필요한 맥락)
  │        │
  │        ▼
  ├─ 의사결정 모듈: 목표·판단 정보, 결정 요청·대안·승인, 타임라인, 기록(결정·변경 이력)
  ├─ 실행·자원관리 모듈: 팀원 상태, 배정안 → 담당자 확정, 맥락 전달, 기록(배정·진행 이력)
  └─ 공통 기반: 사용자·권한, 설정, 비밀 값 보관, 앱 입력·변경 수집, 원본 저장소
```

## Discord 자동 인식 흐름

1. Discord에서 새 메시지를 수집한다.
2. Gemini가 새 목표·작업 후보를 찾는다.
3. 후보는 "제안" 상태로 근거 메시지 링크와 함께 저장되고, 대시보드는 아직 바뀌지 않는다.
4. 앱이 새 목표·작업을 인식했다고 알린다.
5. 사용자가 추가하면 목표·작업으로 반영하고, 거절하면 후보를 닫는다. AI가 스스로 추가하지 않는다.

## 아직 정하지 않은 것

- Gemini가 실패하거나 키가 없을 때 앱 입력을 막을지, 대기열에 두었다가 정제할지
- 정제 전 원문(Discord 메시지, 변경 전후 값)을 근거용으로 따로 남길지
- 자동 인식 알림 대상, 추가 전 후보 편집 허용 여부, 기존 항목 변화도 인식할지, 인식 주기
- 상시 운영 환경과 영구 저장소, 사용자·관리자 권한 체계
- 의사결정 입력 양식의 필수 항목, 결정 승인 절차
- 팀원 정보 입력 주체, 가용 시간 단위, 배정 방식, "자원"의 범위
